The problem

Access grows faster than anyone can track it.

The bigger a team gets, the more passwords, API keys and portals it collects. Without an overall view, nobody can say who has access to what, or who did what.

01

Shared credentials

Passwords travel by email, chat or spreadsheet. When someone leaves the team, nobody knows what they still know.

02

Portals with no API

Many suppliers only offer a web portal. Repetitive tasks are done by hand, often with a shared account.

03

No clear trail

When an invoice is downloaded or a setting is changed, it is hard to know who did it, in what capacity and with what approval.

Live access

Every event carries a group and a role.

The access feed shows, live, who, user or agent, is accessing which portal, credential or API. Every event shows the security group and the role of the person or agent.

  • User or agent, portal, credential or API
  • Security group and role on every event
  • Approvals visible in the feed
  • Instant revoke from the console
  • Hardware security key events
  • Audit log of every action

Security groups and roles

Clear rights, by group and by role.

Every person and every agent belongs to a security group and has a role. Rights follow the role, not someone’s memory.

Roles

  • AdministratorConfigures groups, roles, the vault and APIs.
  • ApproverApproves or declines access requests and sensitive actions.
  • OperatorUses the portals and credentials their group allows.
  • Read onlyViews the feed and the log, without changing anything.
  • AgentRuns defined tasks on named portals, within a set scope.

Example groups

  • Finance
  • Operations
  • IT
  • Leadership
  • Automated agents

Groups are defined with you, to match your organization.

  • ApprovalsA sensitive action waits for an approver.
  • Instant revokeAccess, a session or a key is withdrawn in one step.
  • SSOSign in with your organization’s identity provider.
  • Audit logEvery action is kept with who did it, their group and their role.

Physical authentication

A physical key for the actions that matter.

Warden Liaison supports physical authentication with hardware security keys such as YubiKey (FIDO2, WebAuthn, passkeys). A stolen password is no longer enough.

  • Required by group or roleA hardware key can be mandatory for a security group or a role, for example Finance or Administrator.
  • Enrollment and inventoryEach member enrolls their key. The inventory shows which keys belong to whom.
  • Lost key, revoked keyA lost key is revoked immediately from the console.
  • Step up for sensitive actionsOpening the vault, approving or revoking can require a touch on the physical key.
  • Visible in the feedKey events appear in the live access feed, with group and role.

YubiKey is named as an example of a compatible key. No partnership is implied.

Questions

Frequently asked questions.

Do our suppliers need to offer an API?
No. When an API exists, Liaison manages it in the API manager. When there is only a web portal, a Liaison agent uses it with credentials from the vault.
Do users see the passwords?
No. Secrets are injected at the moment of access without being shown, to users or to agents.
Where is our data hosted?
The console, the credential vault and the logs are hosted in Canada.
Is Liaison only for large companies?
Liaison is built for large teams, but it also suits smaller organizations that want to know who accesses what.
Can access be removed immediately?
Yes. Access, a session or a key can be revoked from the console. The revocation is recorded in the audit log.
Does Liaison support hardware security keys?
Yes. Liaison supports hardware security keys such as YubiKey (FIDO2, WebAuthn, passkeys). A key can be required by group or role, and confirmed for sensitive actions such as opening the vault, approving or revoking. A lost key is revoked from the console.
How does a project start?
With a discovery of your portals, credentials and teams, then setup of groups, roles and the vault, and a pilot on named portals before deployment.
Does Liaison replace a compliance certification?
No. Liaison provides verifiable controls and records that help show who accessed what. It is not a certification.
